# Рефлексия

## В общем о проекте

Решил использовать C + SDL3(графика), было интересно узнать как ИИ будет себя вести в разработке игр/визуала/звука.
Идея простенькая - летать за птицу в горах. 

## Настройка окружения

Попросил создать MCP, скиллы, сказал что-бы после каждого изменения делала коммиты согласно git-conventional-commits, утвердил C Linux Kernel Guidelines для кодстайла. В целом со всем этим он справился сам.

## MCP

Попросил чтобы он сам написал mcp для подтягивания информации для SDL3, у него все получилось. mcp предоставляет список хэдеров SDL3, дает возможность искать определения, документацию и тд.

## Skills

ИИшка создала скилл для корректной работы с SDL3. Довольно много в нем посвящено различиям между SDL2 и SDL3, так понимаю что много источников на SDL2, и он посчитал нужным добавить эту часть. Также в скилле описана работа с mcp.

## Hooks

Сделал хук по верификации кода - он должен компилироваться, должен проходить по кодстайлу. Попросил сделать его максимально детерменированным, вроде получилось.

## Работа, итоги

После настройки окружения попросил написать базовый MVP. Все прошло успешно, базовая программа работала, он сам же сразу закоммитил.
Дальше продолжал давать запросы, думал что результат будет хуже, оказался довольно хорош. 

- Работа с графикой: Было пару моментов, когда просил изменить что-то визуальное, и все ломалось, но в итоге получалось добиться нужного результата. Все же специально была выбрана низкополигонная графика для удобства ии-генерации.
- Аудио: Он сам сгенерил его, без каких-либо сторонних ассетов, и получилось не так уж плохо, но все же режет слух моментами.

Подводя итоги, я за пару часов небольшого внимания проконтроллировал написание игры, которую сам бы писал как минимум пару дней прилагая большие усилия. Сам сетап и воркфлоу довольно приятные - с хуками, mcp и скиллами процесс чувствуется увереннее, вроде нету такого что ии делает то чего не нужно. Чувствуется
